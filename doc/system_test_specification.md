## 1. 総合テスト方針

- **対象スコープ**: 要件定義書に掲げられた全機能要件、非機能要件、セキュリティ要件、運用シナリオの網羅的検証。
- **実行形式**:
  1. CLI自動総合テストシナリオ実行（`tests/run.php`）
  2. 実環境（さくらインターネット等のレンタルサーバー環境）を模したシナリオ検証
- **合格基準**: 全シナリオが期待通りの振る舞いを示し、要件定義書で定義されたすべての仕様を満たすこと。

## 2. 総合テストシナリオ一覧

### 2.1 エンドツーエンド 業務シナリオテスト

| シナリオNo | シナリオ名 | 実施手順 | 期待結果 (要件定義充足基準) |
| :-: | :--- | :--- | :--- |
| ST-01 | **PCユーザー向け Web手動ダウンロードシナリオ** | 1. WebブラウザでポータルTOP（`index.php`）にアクセス<br>2. ツール一覧から目的のツールを選択して詳細画面を開く<br>3. 最新バージョンのフルZIPまたは差分ZIPの「ダウンロード」を押下 | - ツール詳細、リリースノート、SHA256ハッシュが確認できる<br>- 正しいZIPがダウンロード完了する<br>- `download_logs_YYYY-MM-DD.jsonl` に正確な接続元IP、逆引きホスト名、国名（JP等）が記録される |
| ST-02 | **アップデータEXE連携 自動最新化シナリオ** | 1. アップデータEXEから `GET api.php?action=check` を実行<br>2. 新バージョン情報（URL、差分ZIP、SHA256、削除ファイル一覧）を取得<br>3. `GET api.php?action=download` で差分ZIPを取得 | - アップデータEXEに必要な全メタデータが即座に返却される<br>- 差分ZIPが省メモリでストリーム配信される<br>- DLログに `client_type: updater_exe` として記録される |
| ST-03 | **新リリース発生 ＆ 自動パッケージ生成シナリオ** | 1. 管理対象リポジトリで新規リリース（例: `v2.2.0`）を公開<br>2. ReleaseHubにアクセス（または手動同期実行） | - 新規バージョンが自動検知される<br>- GitHubアタッチZIPの取得またはソースからの差分ZIP生成が自動完了する<br>- `manifest.json` が更新され、ポータルおよびAPIに即時反映される |
| ST-04 | **外部通知連携シナリオ (RSS / Webhook)** | 1. 新リリース生成が完了<br>2. 設定されたWebhook URL（Discord等）およびRSSフィードを確認 | - Webhookに「ツール名、バージョン、リリース日時、変更点、DL URL」の通知が即時送信される<br>- `feed.php?type=rss` に新リリース項目が追加される |

### 2.2 非機能要件・耐障害性テスト

| シナリオNo | 検証項目 | 実施方法・負荷条件 | 合格基準 (要件定義4.9節) |
| :-: | :--- | :--- | :--- |
| ST-05 | **メモリ制限（128MB）適合テスト** | 50MB〜100MB超のダミーZIPファイルをダウンロード配信 | PHPメモリピーク使用量が10MB未満に抑えられ、メモリ枯渇エラーを起こさずにストリーム配信が完了すること |
| ST-06 | **タイムアウト制限（30秒）適合テスト** | 通常のWeb画面アクセスおよびAPI呼び出しの実行時間を計測 | キャッシュ利用時は **0.1秒未満**、リリース同期時も **3秒未満** で処理が完了すること |
| ST-07 | **サブディレクトリ配置完全対応テスト** | ドキュメントルート配下のサブディレクトリ（例: `/releasehub/`）に配置して全ページ遷移を実行 | ドキュメントルート（`/`）に強制遷移せず、すべてのリンク・画像・CSS・APIがサブディレクトリ内で完結すること |
| ST-08 | **日別ログローテーション検証** | 日付を跨いだ連続ダウンロードシミュレーション | 各日付ごとの `download_logs_YYYY-MM-DD.jsonl` に正しくログが振り分けられ、過去ログの肥大化による集計遅延が発生しないこと |
| ST-09 | **GitHub APIレートリミット耐性テスト** | GitHub APIがHTTP 403 (Rate Limit) を返す極限状態でアクセス | 画面がクラッシュせず、既存の保持データ（manifest/ZIP）でポータル・API配信を100%継続すること |

### 2.3 セキュリティ・運用管理テスト

| シナリオNo | 検証項目 | 実施手順 | 合格基準 (要件定義4.8節) |
| :-: | :--- | :--- | :--- |
| ST-10 | **Web編集機能排除（リードオンリー）検証** | Webポータル上の全画面・全エンドポイントを調査 | 管理者ログイン、ツール編集、ファイルアップロード等の攻撃対象となり得るWeb管理画面が一切存在しないこと |
| ST-11 | **設定・ファイル配置による運用管理検証** | `server/config/branches.json` に新ツールをファイル直接追記 | Web画面の再読み込みで、即座に新ツールが一覧・詳細に反映されること |
| ST-12 | **重要ファイルへの直接アクセス遮断検証** | ブラウザから `config/branches.json` や `storage/logs/` のURLへ直接アクセスを試行 | `.htaccess` 等により 403 Forbidden で遮断され、設定情報やログが生公開されないこと |
